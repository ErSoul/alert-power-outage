# alert-power-outage

A collection of POSIX shell scripts that alert when a machine loses power (or comes back on), using SMS, email, [ntfy.sh](https://ntfy.sh) or WhatsApp.

| Script | Purpose |
| --- | --- |
| `notify-server-up.sh` | Notify when the computer has powered on (SMS and/or email). |
| `notify-termux-plugged.sh` | Notify when a Termux device is plugged/unplugged from AC power. |
| `notify-network-plugged.sh` | Notify when a host on the network becomes reachable/unreachable. |

# NOTIFY SERVER IS UP (SMS)

## DESCRIPTION

Notifies when the computer powered on using the [Telesign](https://portal.telesign.com/signup) or [Twilio](https://www.twilio.com/login) API, and optionally by email.

The script uses a `.env` file located next to the script that should contain the variables needed for the script to work properly.

## USAGE

After setting up the values in the `.env` file you should add the following to your crontab:

`@reboot /path/to/your/script/notify-server-up.sh --twilio "Server is up" >> /var/log/notify-sms.log`

Exactly one of `--twilio` or `--telesign` must be specified.

### OPTIONS

- `--twilio` — Use the Twilio service API.
- `--telesign` — Use the Telesign service API.
- `--email` — Also send an email notification (requires `sendemail`).
- `-h`, `--help`, `--usage` — Show the help message.

### ENVIRONMENT VARIABLES

| Variable | Required | Description |
| --- | --- | --- |
| `CUSTOMER_ID` | yes | Account SID for Twilio / Customer ID for Telesign. |
| `API_KEY` | yes | API key for the selected service. |
| `URL` | yes | Service API endpoint. |
| `PHONE_TARGET` | yes | Destination phone number. |
| `PHONE_SRC` | Twilio only | System (from) phone number. |
| `SMTP_HOST` | `--email` | SMTP server host. |
| `SMTP_PORT` | `--email` | SMTP server port. |
| `FROM_ADDRESS` | `--email` | Sender email address. |
| `FROM_PASSWORD` | `--email` | Sender email password. |
| `TO_ADDRESS` | `--email` | Recipient email address. |

## NOTES

For some reason the `base64` string generated by the `telesign_encode_credentials` function differs on the last character, in contrast of the one generated in https://developer.telesign.com/enterprise/reference/sendsms. That's why I had to add the `sed s/K$/=/` to the output, but in normal circunstances I guess it shouldn't be needed.

Note that the value for *PHONE_TARGET* must have the _+_ character as prefix when using *Twilio*, but not for *Telesign*.

# NOTIFY TERMUX IS PLUGGED

## DESCRIPTION

This script will alert when the server has been unplugged from AC Power. and when it's connected again. It does that by getting the current status from **$STATE_FILE**.

It is recommended that **$STATE_FILE** should be in a volatile mountpoint, like a **tmpfs** filesystem, though, not a requirement...

The notification goes through a [ntfy.sh](https://ntfy.sh) topic and/or WhatsApp through the [Evolution API](https://doc.evolution-api.com).

The script requires `curl`, `jq`, `flock` and `termux-api`, and optionally sources a `.env` file located next to the script.

## USAGE

`* * * * * /path/to/your/script/notify-termux-plugged.sh -s /dev/shm/state --ntfy-topic $NTFY_TOPIC >> /var/log/termux-power.log`

### OPTIONS

- `-s FILE` — File to read previous state.
- `--ntfy-topic NTFY_TOPIC` — Set topic from https://ntfy.sh.
- `--ws-api-key API_KEY` — Set topic from https://doc.evolution-api.com/v2/en/env#authentication.
- `-h`, `--help`, `--usage` — Show the help message.

### ENVIRONMENT VARIABLES

| Variable | Required | Description |
| --- | --- | --- |
| `STATE_FILE` | yes | Same as `-s`. |
| `NTFY_TOPIC` | yes | Same as `--ntfy-topic`. |
| `EVOLUTION_API_KEY` | WhatsApp | Same as `--ws-api-key`. |
| `EVOLUTION_API_FQDN` | WhatsApp | Evolution API host. |
| `EVOLUTION_API_INSTANCE` | WhatsApp | Evolution API instance name. |
| `WS_PHONES` | WhatsApp | Destination phone numbers (comma/space separated). |

# NOTIFY NETWORK IS PLUGGED

## DESCRIPTION

This script alerts when a host on the network becomes reachable (power on) or unreachable (power outage). It does that by pinging **TARGET** and comparing the result with the previous status stored in **$STATE_FILE**.

The notification goes through a [ntfy.sh](https://ntfy.sh) topic. Optionally, every status change is appended to a CSV file.

Unlike the other scripts, this one does not source a `.env` file; the values can be passed as options or exported in the environment.

## USAGE

`* * * * * /path/to/your/script/notify-network-plugged.sh -t $NTFY_TOPIC -f /dev/shm/state -l "SOMEWHERE AROUND" 192.168.1.10 >> /var/log/network-power.log`

### OPTIONS

- `-f FILE` — File to read previous state.
- `-t TOPIC` — NTFY topic name.
- `-o CSV_FILE` — Output file for historic.
- `-l LOCATION` — Set a label for the location.
- `-h`, `--help`, `--usage` — Show the help message.

### ENVIRONMENT VARIABLES

`STATE_FILE`, `TOPIC`, `OUTPUT_CSV_FILE` and `LOCATION` can be set in the environment instead of (or as defaults for) the matching options. **TARGET** must be passed as the last positional argument.

Note that when *LOCATION* contains spaces it must be quoted, e.g. `-l "NEW YORK"`, so it is parsed as a single value.
